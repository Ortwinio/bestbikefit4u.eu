# Step 04 — Feedback Hub And User Follow-Up

## Goal

Align the user-facing history/status experience with the new panel-first submission flow.

## Tasks

1. Reposition `/feedback` as the owned feedback hub, not the main creation surface.
2. Keep or refine these tabs as appropriate:
   - My Submissions
   - Feature Requests
   - Changelog
3. Make the primary CTA on `/feedback` open the right-side panel.
4. Ensure users can see:
   - their submitted items
   - visible admin replies
   - linked release information
   - a clearer lifecycle status that explains progress in plain language
5. Verify dashboard-message replies and feedback-detail replies remain aligned.
6. Remove or adapt outdated wording that still describes the old modal/dialog flow.
7. Add clear post-submit expectation language so users understand:
   - that their feedback was received
   - where replies will appear
   - how shipped fixes may be referenced back to them

## Deliverable

- updated `/feedback` hub behavior
- consistent detail surface strategy
- reply/status loop aligned with admin messaging
- clearer user lifecycle/status contract

## Done When

- `/feedback` complements the panel instead of competing with it.
- Users can submit from anywhere and review status in one consistent place.
- The feedback lifecycle is understandable without internal product terminology.
