# Icon System Consistency

## Objective

Create and apply a consistent icon contract across public pages so icons feel purposeful, recognizable, and commercially polished rather than ad hoc.

## Inputs

- [page.tsx](/Users/ortwinverreck/Developer/bestbikefit4u/src/app/(public)/page.tsx)
- [PublicPrimitives.tsx](/Users/ortwinverreck/Developer/bestbikefit4u/src/components/public/PublicPrimitives.tsx)
- [Header.tsx](/Users/ortwinverreck/Developer/bestbikefit4u/src/components/layout/Header.tsx)
- [Footer.tsx](/Users/ortwinverreck/Developer/bestbikefit4u/src/components/layout/Footer.tsx)
- Output from Step 01

## Tasks

1. Inventory current icon usage across public marketing, conversion, navigation, and CTA surfaces.
2. Define an icon contract covering:
   semantic meanings, canonical icon choices, sizes, stroke weights, wrapper treatments, and color usage.
3. Identify where icons currently change meaning from page to page or appear decorative without purpose.
4. Extract shared icon helper patterns if needed for feature cards, trust strips, stat panels, and CTAs.
5. Apply the contract to homepage, pricing, calculators, FAQ, contact, header, footer, and shared public primitives.
6. Remove icon inconsistency that weakens product clarity:
   mismatched badge icons, repeated random icon assignments, and uneven icon containers.
7. Verify icons remain legible and consistent in both light and dark themes.

## Deliverable

A documented and implemented public icon system with consistent semantic usage and styling.

## Completion Checklist

- [ ] Canonical icon meanings are documented.
- [ ] Shared icon wrapper treatment is consistent.
- [ ] Major public pages use the same icon rules.
- [ ] Decorative-only icon drift is reduced.
- [ ] Light and dark theme legibility is verified.
