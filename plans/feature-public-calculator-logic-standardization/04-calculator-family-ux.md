# Step 4: Calculator-Family UX Contract

## Objective

Define one UX structure for all public calculators so they feel like one product family.

## Tasks

1. Define the shared page/form structure:
   - what this tool is for
   - required inputs
   - optional refinements
   - result
   - why this result changed
   - next best action
2. Define interaction patterns for:
   - required vs optional sections
   - measurement help
   - inline explainers
   - “how to measure” drawer
   - quick retake actions
3. Define how dependency logic is shown:
   - primary drivers
   - secondary modifiers
   - not covered here
4. Define shared confidence and explanation placement in the UI.
5. Use the tire-pressure calculator as the closest reference, then generalize it for the fit tools.

## Output

Create `output-04-calculator-family-ux.md`.

## Success Criteria

- Public calculators share the same structural rhythm.
- Measurement friction is handled at the point of entry.
- The UX supports explainability rather than hiding the logic behind the final answer.
