# R8 final-contract review

Read-only review against PLAN §7, RP7 board, `shared/advice/types.ts`, A's final integration/query messages and actual `convex/advice/{queries,groupAdvice,mutations,recalculateState}.ts`. Only this note was written; no source/tests/backend changes or live calls.

## Critical display rules

1. **Reliability is already 0–100, not 0–1.** groupAdvice converts fit item confidence ×100, falls back to report confidenceScore, and uses saddle/gearing scores directly, clamping to 0–100. Do not multiply again or pass directly to a fraction-based formatter. Zero is a real value; null means unavailable, not 0%. Reason is only engine_confidence / unknown / saved_inputs_only. This is engine confidence, not A's rider-profile reliability score or a statistical confidence interval. No group aggregate or high/medium/low threshold is supplied: RP7's group reliability chips cannot be reproduced honestly by inventing an average or threshold.
2. **Unknown is not fresh.** A legacy row has `staleness={stale:false,status:"unknown",reasons:[legacy_provenance]}` but can still have item `status:"new"`. Branch on staleness.status, not only stale boolean/item status; don't show an unqualified green “new/current” badge for unknown. Recalculation eligibility includes unknown and needs_calculation as well as stale. Saved-input rows have null value/range and reason saved_inputs_only; the date is a state-save date, not proof of a calculation.
3. **Pending is not updated.** Fit recalculation returns `source:"recommendations"`, id=old recommendation record id, and replacementId=**new fit session id**, not replacement recommendation/item id. Keep the old report, values, original date, stale/unknown qualification and old source link while pending. Join the local pending state to rows by recordId, not item.id. Multiple visible rows can share one record and one pending result; counts are records, not advice rows.
4. **Only fresh query data can replace rows.** Mutation completion or status updated must not locally clear stale/unknown flags. Render the reactive query's returned state; updates can become stale again if inputs change. Show separate updated/pending/skipped/failed result counts. Skipped/failed preserve existing advice. Do not offer a blanket “everything is current” success message for a mixed/empty response. Pending background fit failure/completion is not persisted as a job status in this query contract; after reload this client cannot reconstruct a pending state from the groups alone. Keep that limitation explicit rather than inventing completion.

## Requirements covered and genuine gaps

- Seven stable groups, including empty groups, are supplied. Keep returned per-group item ordering: changeOrder ascending, date descending, then id. Do not regroup/sort by translated title or reliability. Date is epoch milliseconds; no measurement date is supplied here.
- Targets are number|string|null; frameSize is an exact engine string and can have unit="". Never parse its midpoint or append a unit. Range, current and difference are genuinely nullable; show unavailable/omit rather than fabricate. Preserve signed and zero differences, including zero current values. Numeric difference is already target−current in the same unit.
- PLAN/RP7 includes performed and waiting-for-ride-feedback statuses and a “mark performed” action. Actual API has only new/stale/needs_calculation and no such mutation. Do not infer performed from difference=0, fit-session completion or recalc success. This requirement remains an explicit backend/product gap.
- Generic reliability reasons exist, but the API does not expose the board's detailed explanations (“estimated from height”, “measured sit bones”), adjustment-step instructions or source measurement kinds per row. Stale reasons identify fields/record scope but **not old/current values or change dates**; the illustrative 70→68 kg/date banner cannot be reconstructed from this response. Use neutral localized reasons.
- Improvements are zero to three positive **theoretical profile-score gains**, already sorted. They are not promised advice-confidence gains, completeness gains or narrower measurement ranges. `field` currently equals the score rule key (e.g. inseam, footwear), not a profile field path. Links currently lead to `/profile`; do not feed these keys to a field mutation or promise the board's ±12→±8 mm improvement. Empty groups/actions must not be padded with invented advice.
- `current` for fit items is read from the live bike, but saddle-width/pressure current values come from their saved source records. The client cannot claim every “current” number was just measured or reflects the latest live bike setup; there is no per-current timestamp in the response.
- Actual calculator outputs exist after explicit recalculation, but no ranges/confidence/current values are carried for these saved outputs. Bike-fit calculator-state outputs (including barDrop/reach/frame outputs) are currently all placed in seating by calculator id; this differs from the full recommendation's semantic cockpit/frame grouping. Flag to A if strict cross-calculator grouping is required; do not silently reimplement backend grouping in the route.
- The message's output-key list is incomplete: actual bike-fit state output also emits saddleSetback, barDrop, saddleToBarReach, frameStack and frameReach. Localized labels need these as well as the documented keys. `AdviceItem.key` is an unrestricted string, so a safe unknown-key label is still needed.

## Filtering, links and recalculation scope

- listAdviceGroups({bikeId}) excludes rider-only items; it does not mean “rider + selected bike.” For all/rider/bike tabs, querying all and filtering by exact item.bikeId is viable. Rider is null. Bike names come from the separate owned bikes query; do not hardcode RP7 examples. Filter items within groups, not just group scope; a group can contain multiple bikes and rider rows.
- Filtering all-group results client-side leaves the group's theoretical rider improvement actions unchanged; no bike-specific improvement contract exists. An unknown/deleted selected bike should produce a safe empty/reset state, not silently display another bike's advice.
- Source links are local account routes; apply the locale helper. Several calculator links (`/saddle-selector`, `/gearing`, `/pressure-calculator`, `/tools/...`) omit bikeId, although item.bikeId is supplied. Confirm desired scoped navigation; append only an existing supported bike-id parameter, never values. Fit links already identify the exact old report session.
- **recalculateAll({}) has no bike filter and currently recalculates latest records regardless of freshness.** Do not label the action “only this bike” or “only stale advice” unless A changes that contract. It processes all owned latest source scopes, even while a tab filters the screen. Its result count may exceed visible rows; pressure recalculation also distinguishes sourceType while the query shows only latest pressure per bike.
- Mutation reasons currently include BIKE_UNAVAILABLE, MISSING_CURRENT_INPUTS, FIT_UNAVAILABLE, FIT_ALREADY_PROCESSING and CALCULATION_FAILED. Localize those known codes with a generic fallback; don't expose raw backend messages or pretend missing inputs were filled. FIT_ALREADY_PROCESSING is skipped, not a new pending job.
