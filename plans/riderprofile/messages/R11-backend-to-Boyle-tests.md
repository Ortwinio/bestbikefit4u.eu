Fake runMutation routers must dispatch by function name, not always route to update. This separates the trusted token disable path (no consent needed) from explicit browser preference requests (consent required whenever newsletter is supplied).

Public preferences:set and signed preferenceActions:save retain required service/marketing; newsletter and consent optional. Omitted newsletter preserves current state/metadata and does not query or insert receipts. Existing fixtures should expect normalized newsletter=false on reads/writes.

Replay returns current preferences and newsletterGranted=false without any writes, including service/marketing writes. Different payload reuse of a consumed key is inert. No-op receipts are necessary so a request made while subscribed cannot later re-enable after unsubscribe. Real Convex transaction atomicity handles concurrent requests and rollback; fake ctx tests need query/insert support.
