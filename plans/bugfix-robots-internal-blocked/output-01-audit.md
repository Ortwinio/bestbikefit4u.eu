# Output 01 — Robots Policy Audit

## Source Of Truth

Current robots output is generated by:

- `src/app/robots.ts`
- `src/lib/seo/sitemap/config.ts`
- `src/lib/seo/routePolicy.ts`

The crawl report in `docs/issues_overview_report.csv` reported `86` internal URLs blocked by robots.txt.

## Before

Production `robots.txt` disallowed all of these groups:

- private app routes: `/dashboard`, `/fit`, `/bikes`, `/profile`, `/settings`, `/feedback`, and locale variants
- auth routes: `/login`, `/en/login`, `/nl/login`
- API/system routes: `/api`, `/trpc`, `/static`, `/_next`
- crawler utility endpoints: `/robots.txt`, `/sitemap.xml`, `/sitemap-pages.xml`, `/sitemap-calculators.xml`, `/sitemap-guides.xml`, `/sitemap-blog.xml`

## Decision Table

| Prefix group | Decision | Reason |
|---|---|---|
| Private app routes | Keep disallowed in `robots.txt`; exclude from sitemaps | These are authenticated product surfaces and should not be crawled or indexed. |
| Admin routes | Keep disallowed in `robots.txt`; exclude from sitemaps | Operational/private. |
| API and TRPC routes | Keep disallowed in `robots.txt`; exclude from sitemaps | Non-page endpoints. |
| `/static` | Keep disallowed in `robots.txt`; exclude from sitemaps | Not needed as a crawlable page surface. |
| `/_next` | Allow in `robots.txt`; exclude from sitemaps | Render assets should be fetchable by modern crawlers, but never sitemap URLs. |
| `/robots.txt` | Allow in `robots.txt`; exclude from sitemaps | Crawlers must be able to fetch the policy file. |
| `/sitemap*.xml` | Allow in `robots.txt`; exclude from URL sitemaps | Sitemap files are explicitly advertised and should not be contradicted by `Disallow`. |
| `/login` and localized variants | Allow in `robots.txt`; exclude from sitemaps | Public pages link to login CTAs. The auth layout already emits `noindex, follow`, which crawlers must be able to see. |

## Link Audit

Static inspection found many public CTA links to `/login`, including homepage, pricing, calculators, guide CTAs, footer/header actions, and public content pages. These are intentional conversion paths, so blocking `/login` in robots created avoidable crawler warnings.

Remaining public links to private routes are mostly authenticated-state dashboard CTAs in shared navigation/guide components. Those private route families remain intentionally blocked.
