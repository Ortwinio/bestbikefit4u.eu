# Prompt 04 — Trust Boost And Final QA

## Context

Read:

- `plans/feature-homepage-post-redesign-upgrade/README.md`

Phases 1–3 should be complete first.

This phase adds the highest-leverage remaining trust signals and closes the work with live validation.

## Task

Increase confidence around key decision moments and finish the upgrade with explicit browser QA evidence.

## Deliverables

### 1. Add one stronger aggregate trust signal

Introduce at least one of these, using only claims/data the product can support:

- review aggregate
- “as seen in” strip
- stronger rider-count reinforcement at a decision moment

Place it where it helps conversion most, not where it merely fills space.

### 2. Reinforce the stepper decision moment

Add a small social-proof or adoption cue inside the stepper section or immediately after its CTA.

The purpose is to reassure users at the exact transition from “learn” to “act”.

### 3. Evaluate testimonial identity strength

Review whether one real photo can be used with the existing data/assets.

If yes, implement it carefully.

If not, document why and improve the current initials/avatar treatment so the limitation is intentional rather than placeholder-like.

### 4. Final browser QA and closeout

Perform real browser/manual QA for:

- `/en`
- `/nl`
- one desktop width
- one mobile width

Explicitly verify:

- hero CTA hierarchy
- proof/hero transition
- bike showcase visibility on desktop
- closing CTA copy hierarchy
- cookie-banner color alignment

Record the QA outcome in a plan output file and update the plan README status.

## Constraints

- Do not add fake review data, fake logos, or unverifiable social proof.
- Keep trust additions concise.
- Avoid turning the page into a badge wall.

## Completion Checklist

- [x] At least one new high-impact trust signal is added or intentionally documented as blocked.
- [x] The stepper decision moment is reinforced with social proof.
