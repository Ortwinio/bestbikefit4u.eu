# Marketing batch 19.3 visual validation

Run `node tests/visual/marketing-batch3/capture.mjs` with the local frontend on
port 3000. Set `VISUAL_DEV_ORIGIN` for another port; `VISUAL_FILTER` optionally
narrows case names. Chromium requires loopback/process permission.

The matrix captures Dutch and English at 1440×1000 and 390×844:
live guide library, real saddle-height guide, handlebar-width leaf, geometry hub and blog index;
isolated populated blog, category filter, second page and article fixtures.
CMS currently supplies no published blog article. Synthetic articles are confined
to this test directory and never published or inserted into application defaults.

Blog fixtures render actual routes, shared Header/Footer and components with
compiled Next CSS, local fonts/assets and the theme provider. The real blog data
adapter is retained, with its Convex transport replaced by synthetic data. Only
request locale/navigation/auth, server-only imports, filesystem guide-title lookup
and the asynchronous CSP JSON-LD wrapper are adapted. Schema arguments are still
generated by the real pages. Image/link adapters are reused from account-batch1.
No backend writes or external requests are allowed by the fixture browser.

Live routes exercise real metadata/canonicals/JSON-LD. Fixture screenshots do not
claim to test server metadata injection, CSP headers, authentication or production
CMS connectivity. Route tests separately validate metadata and CMS contracts.

Output is `plans/redesign-canvas/code-renders/19-3-*`: full-page screenshots,
mobile viewport screenshots, four approved board references, and results JSON.
The JSON includes CSS/bundle fingerprints, H1s, canonical links, schema payloads,
image checks, TOC targets and browser errors. Overflow, broken images, missing TOC
targets, multiple/missing H1s or runtime errors fail the run. Consent is dismissed
through its actual control; only Next's developer overlay is hidden for captures.
